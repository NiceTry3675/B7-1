# 모델 응답 품질의 한계

현재 Gemma 3 1B Q4_0와 기본 페르소나 프롬프트에서 관찰한 응답 품질의 한계입니다.
응답의 정확성·문맥 해석·형식 준수는 모델 출력 품질 항목으로 관리합니다.
아래 사례는 가입·인증·API 통신·대화 저장/조회 기능의 실패로 분류하지 않습니다.

## 실제 대화 예시 — 2026-10-19

S7 FE의 Gradio 프론트에서 사용하는 Controller와 FastAPI를 거쳐 RPi5의 실제 CPU 모델을
호출했습니다. 페르소나는 소크라테스이며, 두 질문은 같은 대화에 속합니다.

첫 질문:

```text
진로가 고민돼요. 무엇부터 생각하면 좋을까요?
```

실제 응답:

```text
자, 시작해 볼까요?

**"당신은 지금 어떤 문제에 직면하고 있나요? 그 문제에 대해 조금 더 자세히 말씀해주시겠어요?"**
```

이미 제시한 진로 고민을 구체적으로 짚기보다 설명을 다시 요청했습니다.
또한 평문으로 표시하는 현재 화면에서 `**`와 따옴표가 그대로 드러납니다.

같은 대화의 후속 질문:

```text
처음 말한 고민의 주제를 한 단어로 답해 주세요.
```

실제 응답:

```text
번아웃.
```

처음에 말한 주제는 `진로`였습니다. `번아웃`은 사용자 메시지에 없던 주제로,
이 사례에서는 이전 대화의 의미를 정확히 짚지 못했습니다.
두 응답은 각각 70자와 4자였으며, 이 표본의 문제는 길이보다 내용과 표현입니다.

## 확인한 기능과 관찰 범위

- 실제 Gemma 생성, SQLite의 완료 턴 2개 저장, 재로그인 후 같은 기록 조회를 확인했습니다.
- 동일 질문 UUID 재전송은 저장된 답변을 반환했고, 로그아웃한 토큰은 401로 거절했습니다.
- 로컬 토크나이저와 llama-server의 입력 토큰 수는 두 비교 표본에서 19/19, 40/40으로 일치했습니다.
- 시험용 계정과 대화 데이터는 확인 후 정리했습니다.

이 두 턴의 기능 검증 통과는 응답 품질을 보장하지 않습니다. 모델 크기·양자화·프롬프트 중
어느 요인이 원인인지는 분리 비교하지 않았습니다. 향후 개선을 검토할 때는 같은 질문으로
프롬프트와 모델 설정을 비교하고, 문맥 회상과 평문 형식 준수를 별도로 평가합니다.
